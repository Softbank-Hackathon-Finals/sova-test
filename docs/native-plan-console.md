# 실제 운영 계획 콘솔 연결

2026-11-08. 기존 Sova 관측 화면을 유지하면서 팀 플랫폼의 계획·이벤트·승인 콘솔을 연결하는 개인 호스트 어댑터다. 실제 이전 완료 보고가 아니다.

## 재사용 기준

- 관측 화면 기준: sova-test `e26682df26eab47431018fa56485cc2c07d19007`.
- 네이티브 콘솔 기준: platform `a26fabe3ae0eafdd3cc757fcf1c883251db130dc`의 `services/console/src/bravo_console/static/`.
- 계획 모델, SSE 검증·재연결, 승인 binding, 멱등 키, 결과 미확인 상태의 복구 화면을 그대로 사용한다. 정적 경로와 연결 범위 안내만 추가한다.
- 정적 파일은 고정 SHA의 Git 객체에서 읽는다. 작업 디렉터리 수정본이나 이후 develop 변경을 자동으로 섞지 않는다. 플랫폼 배포 이미지가 이 SHA와 같다는 뜻은 아니다.
- 기존 플랫폼 OperatorBridge의 읽기 전용 제한과 운영 호스트 설정은 변경하지 않는다. 이 어댑터는 별도 개인 loopback 호스트용이며 기본 상태도 읽기 전용이다.

## 사용 흐름과 권한

1. 기존 개인 세션으로 Sova에 접속한다.
2. 환경 이전 메뉴에서 **실제 운영 계획 콘솔 열기**를 선택한다. 기존 관측·전용 시험 화면은 유지된다.
3. 운영 담당자가 확인한 실제 계획 ID를 연결한다. 과거 보존 계획을 현재 계획으로 자동 선택하지 않는다.
4. 서버의 계획 snapshot과 유한 SSE 이력을 읽고, 다시 snapshot을 확인한 뒤 실시간 SSE를 구독한다. 이력 누락·다른 계획의 이벤트·권한 거부·만료는 원래 콘솔 모델이 차단한다.
5. 운영 변경에는 계획별 실행 시간과 범위를 호스트에서 별도로 설정해야 한다. 이 설정은 작업 조율의 제한일 뿐 권한을 발급하지 않는다. T10이 본인 신원, 계획 권한, 승인 결속과 현재 판정 근거를 다시 검사한다.
6. 승인 요청과 실행 요청은 분리된다. 실제 결과는 T10의 응답·이벤트·영수증으로 확인하며 화면 버튼이나 전용 시험 승인을 운영 완료 근거로 쓰지 않는다.

현재 운영 실행 구간은 **설정하지 않았다**. 운영 승인·컷오버·복귀 POST는 전달되지 않는다. 등록, IaC, 일반 리허설 실행, 임의 워크로드 격리 요청도 이 어댑터의 허용 경로가 아니다.

## 연결부 보호

- 고정 loopback origin과 개인 세션을 확인하고, 다른 origin·호스트·호출자 Authorization·경로 인코딩·허용하지 않은 쿼리를 거부한다.
- AWS는 `bravo-personal`만 사용한다. 짧은 SSO 증명은 호스트에서 생성하고 브라우저·Git·로그에 저장하지 않는다.
- 서버 인증서와 호스트 이름 검증을 모두 사용한다. 현재 승인 API는 사전에 신원을 확인한 서버 인증서의 등록 SAN을 검증한다. tailnet 이름의 SAN 발급과 동일하게 취급하지 않는다.
- upstream은 고정하며 리다이렉트와 환경변수 프록시를 사용하지 않는다. 플랫폼 기존 OperatorBridge와 동일하게 고정 로컬 Host를 전달한다. 실제 운영 호스트의 origin 허용은 변경 실행 전 별도 인수 항목이다.
- 계획별 실행 구간은 최대 1시간이며 허용 경로·승인 종류를 제한한다. 증명 생성 후에도 세션과 실행 구간을 다시 확인한다.
- SSE는 실제 바이트를 전달하고 최대 45초마다 종료해 재연결 시 새 증명을 사용한다. 권한 회수나 스트림 오류가 발생하면 스트림을 닫는다.
- POST는 자동 재시도하지 않는다. 응답 유실은 결과 미확인으로 남기고 원래 콘솔의 멱등 키·영수증 조회 절차를 사용한다.
