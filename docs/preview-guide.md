# Sova

운영 시스템의 환경 차이를 조사하고, 이전·복구 결과를 검증하는 플랫폼을 개발합니다.

현재 구현은 **실제 AWS·Linux VM에 연결된 워크로드 시각화 프리뷰**입니다. 전체 목표 아키텍처나 프로덕션 서비스의 완료를 뜻하지 않습니다.

독립 제품의 목표 구조·이전/복구 계약·보안 경계·운영 수용 기준은 [프로덕션 설계 명세](sova-production-spec-v1.md)에 정리합니다.

P0에서는 독립 도메인 모델·검증 의무·외부 효과 원장을 추가하고 기존 프리뷰의 SG 변경·경로 전환을 연결했습니다. 조사·계획·복구·정리 port와 승인된 계획 단계의 실행 계층도 추가했습니다. 코드 경계와 구현 범위는 [P0 실행 계약](p0-contracts.md)에 있습니다.

계획·승인·조사 snapshot의 [PostgreSQL 저장소](postgres-lifecycle.md)와 실행 직전 승인 재조회를 구현했습니다. [작업·이벤트/outbox](postgres-outbox.md)의 원자적 접수·relay와 [PostgreSQL 실행 원장·앱 소유권](postgres-execution.md)도 추가했습니다. 기존 프리뷰는 SQLite를 유지하며, 웹·실제 큐/워커·기업 인증 연결은 남아 있습니다.

## 실행 화면

등록된 테스트 환경이 실행 중일 때 `http://127.0.0.1:8790`에 접속합니다.

1. **요청 보내기**로 무상태 HTTPS 앱에 메시지를 보냅니다.
2. 응답의 요청 ID·처리 환경을 지도와 요청 기록에서 확인합니다.
3. **연속 요청**을 켜면 이 탭에서 초당 최대 한 번 요청을 보냅니다.
4. **VM으로 전환**, **AWS로 복귀**를 누르면 목적지 응답을 검증하고 이 테스트 게이트웨이의 실제 요청 경로를 바꿉니다.
5. **보안 시험 · AWS 유입 격리**는 통제된 미등록 관리 경로 요청과 실제 AWS 보안 그룹 격리를 실행합니다.
6. **시험 격리 해제**는 그 시험의 원래 수신 규칙만 복원합니다. 요청 경로를 AWS로 자동 복귀시키지는 않습니다.

상단 파이프라인은 실제 단계·소요 시간을 보여줍니다. 단계를 누르면 수집 시각과 확인 결과가 열리며, 실행 이력 선택으로 이전 시험도 볼 수 있습니다. 지도 노드를 누르면 TLS 수신→HTTP 핸들러→응답 생성의 내부 구성과 실행 조건을 보여줍니다. 이 세 구성은 **하나의 컨테이너 내부**이며 독립 마이크로서비스가 아닙니다.

요청 애니메이션은 확인된 응답에서 발생합니다. 실측 처리량은 요청 집계이며 클라우드 전체 트래픽이 아닙니다. 브라우저를 처음 열었을 때 과거 트래픽을 다시 재생하지 않습니다. 연결 실패·오래된 관측은 미확인으로 표시합니다.

## 범위

- AWS의 별도 Fargate 태스크와 기존 Lima Linux VM의 별도 컨테이너에서 작은 HTTPS 앱을 실행합니다.
- 앱은 같은 고정 베이스 이미지와 같은 Python 소스를 사용합니다. 테스트 소스는 태스크 명령과 VM 실행 명령으로 전달하며, 새 서비스 이미지 CI를 구축한 것은 아닙니다.
- 데이터베이스·영속 업무 데이터·게임·기존 배포 경로는 변경하지 않습니다.
- 두 앱은 미리 실행됩니다. 노드 자체를 옮기거나 종료하지 않고 새 요청의 목적지를 바꿉니다. AWS ALB·DNS의 전환은 아닙니다.
- 실제 침해 탐지·범용 자동 사고 대응·DB 이전·무중단 이전·일반 ZIP 자동 배포는 포함하지 않습니다.
- 보안 시험은 고정된 `GET /admin/export-secrets` 요청의 404 거부를 확인하는 **통제된 시험 신호**입니다. 실제 Secret 조회나 악용 공격을 수행하지 않습니다.
- 이후 Sova 전용 AWS 앱 보안 그룹에서 등록된 TCP8443 수신 규칙만 실제 제거하고, AWS API readback과 새 HTTPS 연결의 실패를 확인합니다. 기존 연결을 모두 강제 종료하는 보장이나 전체 호스트 격리는 아닙니다.
- 네트워크 격리 후 VM 요청 응답을 확인합니다. 감염된 이미지·데이터를 복사하지 않으며 AWS 태스크도 삭제하지 않습니다. 격리 구역으로 이동하는 그림은 논리적 분류이고, 실제 실행 위치는 AWS에 남습니다.
- 시험 중 요청 실패가 발생할 수 있으며 실제 지표에 포함합니다. 무중단을 주장하지 않습니다.
- 격리된 AWS로의 경로 복귀는 차단합니다. 명시적인 시험 격리 해제는 실제 침해 사고의 보안 보류를 해제하는 기능이 아닙니다.
- Linux VM은 이 Mac의 Lima입니다. 인터넷 공개 온프렘 환경이나 심사위원용 공개 URL은 아닙니다.
- 제어 상태는 이 프리뷰 전용 로컬 SQLite입니다. Sova 최종 PostgreSQL·내구성 워크플로 구현과 구분합니다.

## 보안과 수명

- localhost 전용 UI, 세션 쿠키, 동일 Origin 및 Host 검사.
- 서버 인증서와 호스트명을 검증하는 HTTPS, AWS SSM 및 호스트 키를 고정한 SSH 터널.
- 전용 AWS 실행 역할·권한 경계. 테스트 앱에는 task role이나 AWS 자격 증명이 없습니다.
- 앱은 비루트·읽기 전용 루트·capabilities 제거로 실행합니다. VM에 Docker 소켓·호스트 디렉터리를 연결하지 않습니다.
- AWS 테스트 TLS 설정은 전용 Secrets Manager Secret에 두며 브라우저에는 전달하지 않습니다.
- 실행 등록은 준비 시점부터 2시간 동안 유효합니다. 두 앱도 기동 후 2시간에 스스로 종료합니다.
- 앱 종료가 Secret·IAM·보안 그룹의 전체 삭제를 뜻하지 않습니다. 별도 정리 도구로 정확한 소유 자원만 삭제합니다. 금액 상한은 아닙니다.
- 운영 제어기는 개인 AWS 신원으로 실행합니다. 다중 사용자 프로덕션 인증·최소 권한 운영까지 완료한 것은 아닙니다.

## 개발

Python 3.11 이상과 `boto3`가 필요합니다. 정적 화면은 빌드나 외부 CDN 없이 동작합니다.

```sh
python preview/server.py
python preview/check_live.py
python -m pytest preview/test_security.py
python -m pytest tests
node --check preview/web/app.js
```

준비 도구 `preview/prepare.py`는 기존 개인 환경의 고정 이미지·네트워크를 참고하는 운영자 전용 스크립트입니다. 다른 계정이나 빈 환경에서 바로 실행하는 범용 설치 도구가 아닙니다. 등록이 있으면 중복 자원 생성을 거부하며, 실패 후에는 기록과 실제 자원을 확인해야 합니다.

비밀 설정·실행 등록·검증 결과·개발기록은 `.local-notes/`에만 저장하고 Git에서 제외합니다. Sky 및 OneDeploy 소스를 수정하거나 커밋·푸시하지 않았습니다.

## 워크로드 보안 시각화 검증

- 실제 AWS 수신 규칙 제거·새 HTTPS 연결 거부·VM 응답 확인·원래 규칙 복원을 검증했습니다.
- 브라우저 버튼으로 같은 흐름을 확인하고, 파이프라인 실행 중 표시·격리 노드·끊긴 연결·근거 조회·이력 선택·모바일 레이아웃을 확인했습니다.
- 소유권·계정·다른 유입 경로·실행본·네트워크 바인딩이 다르면 변경을 거부합니다.
- 대기 환경 검증 실패, 효과 응답 유실, 동시 실행, 서버 재시작, 인증서·HTTP 오류 오판 방지, 등록 만료 등 22개 단위 시험을 통과했습니다. 이는 fault injection이며 실환경 보안 시험과 구분합니다.
- SQLite에 실행 단계와 결과를 남깁니다. 서버 재시작으로 결과가 불명확한 단계는 `needs_attention`으로 보존하며 외부 변경을 자동 재실행하지 않습니다. 분산 워커·리스·서명된 감사 체계의 완료를 뜻하지 않습니다.

로컬 검증 결과는 `.local-notes/live-preview/live-security-check.json`, `security-browser-check.json`에 있습니다. 비공개 구성과 개발기록은 Git에 올리지 않습니다.

### 격리 해제 직후 재검증

수신 규칙 복원과 실제 HTTPS 연결 준비는 다른 사실입니다. 초기 구현은 복원 직후 한 번의 4초 연결 확인만 사용해 일시적인 연결 지연을 실패로 남길 수 있었습니다. 현재는 읽기 전용 HTTPS 상태 확인만 최대 4회 수행하고, 각 결과를 단계 근거로 보존합니다. 수신 규칙 변경이나 응용 POST를 자동 반복하지 않습니다. 인증서·실행 신원 불일치는 즉시 실패하며, 확인 한도를 넘으면 계속 `needs_attention`으로 남깁니다. 기존 실패 이력을 성공으로 고쳐 쓰지 않습니다.

격리 확인에서도 인증서·TLS·HTTP 응답 오류나 연결 reset을 차단 성공으로 취급하지 않습니다. 정확한 SG 차단 상태와 새 연결의 timeout/refused 결과를 함께 확인하며, 확인 실패는 조정 필요로 남깁니다. 연결 끊김 때는 새 요청·조작을 막고 현재 지표·격리 표시를 미확인으로 전환합니다. 만료는 화면과 서버 양쪽에서 검사합니다. 선택한 과거 실행은 `이력`으로 표시합니다.

이 마무리 흐름은 실제 브라우저에서 SG 격리→VM 요청→시험 해제와 AWS↔VM 왕복 요청을 검증했습니다. 연결 끊김·만료 화면은 같은 임시 브라우저 안의 장애 주입으로 별도 확인했습니다. 기록은 `.local-notes/preview-finish-20261031/`에 보관합니다.
