# 워크로드 대응 유형별 목업 — 2026-11-09

## 목적과 기준

사용자 요청에 따라 실환경을 연결하기 전에 대응 유형과 시각적 동작을 검토한다.
기준은 Sova 기존 콘솔 `e4574806cd8b77da2987f82f288ca506f81c3d36`이다.
독립 작업 브랜치 `feature/workload-response-scenarios`에서 구현했다.
기존 실관측·시험 실행·마이그레이션 경로와 자격증명을 변경하지 않았다.

기존 Sova의 배색·사이드바·카드 스타일을 사용한다. 통합 호스트의 사이드바에는
별도 탭으로 여는 `대응 유형` 링크를 추가한다. 기존 콘솔을 대체하지 않는다.
이번에 실행한 서버는 정적 목업 서버이며 실관측 호스트가 아니다.

14개 가상 자원과 18개 연결을 표시한다. 노드 선택 시 직접 대응 범위와 연결 상태,
인접 영향 가능성을 보여준다. 정상·주의·격리·준비·교체·미확인 상태를 구분한다.
지도 확대·축소, 수동 단계 진행, 자동 재생·중지, 재생 간격, 초기화,
검증 결과 통과·실패·불명확 선택과 JSON 기록 내보내기를 제공한다.

## 승인·실패 경계

- 일반 자동 재생은 승인 단계에서 멈춘다. 대기 시간이 사람 승인을 만들지 않는다.
- 제한된 유형만 범위가 고정된 사전 승인 목업을 선택할 수 있다.
- 대응 유형을 바꾸면 기존 사전 승인과 재생 타이머를 초기화한다.
- 검증 실패·불명확은 보류로 끝난다. 대체 경로나 목적지 writer를 활성화하지 않는다.
- 격리 결과가 미확인이면 격리 완료·차단 확인 수에 포함하지 않는다.
- 완료와 일반 승인은 사고 보류를 자동 해제하지 않는다.
- 앱 롤백과 데이터 복원, 앱 재시작과 환경 이전을 구분한다.

이 규칙은 브라우저 시뮬레이터의 동작이다. 운영 정책 엔진이나 실행 권한이 아니다.

## 연결하지 않은 것

클러스터·T10·T19·T31·모델·scanner·DB·Secret·실탐지 생산자를 호출하지 않는다.
정적 자원 외 HTTP 요청, SSE, WebSocket, 외부 CDN은 없다.
페이지 CSP의 `connect-src 'none'`으로 연결을 차단하고, 독립 서버는 고정 파일만
제공한다. 제품 API 경로는 404, POST·PUT·PATCH·DELETE는 405다.
127.0.0.1에만 바인딩한다. 이 서버를 공개 운영 인증 서버로 사용하지 않는다.

사용자 요청으로 화면의 목업·가상·모의·시뮬레이션 안내와 배지를 제거했다.
제목·지도·단계·승인·타임라인은 중립적인 대응 용어로 표시한다.
JSON의 `provenance: mock`, `actual_execution: false`와 내부 출처는 유지한다.
표시 문구만 변경했으며 실제 환경 연결이나 실행 권한은 추가하지 않았다.
UI의 완료·검증·지표·writer 표시는 실제 이전,
격리, 무중단, 데이터 무손실, 금융 보안 적합성의 증거가 아니다.

## 실행

저장소 최상위에서 Python 표준 라이브러리만 사용한다.

```sh
python3 -m demo.response_scenarios --port 18132
```

브라우저에서 `http://127.0.0.1:18132/console/`을 연다.
정적 파일은 서버 시작 시 읽으므로 수정 후에는 해당 목업 서버를 재시작한다.
실관측 콘솔에 합칠 때는 새 정적 자원과 링크만 추가되며,
기존 호스트 실행 자체의 실환경 연결까지 목업으로 바뀌는 것은 아니다.

## 이동 애니메이션 추가

사용자가 요청한 이전 워크로드 지도와 같은 이동 표현을 추가했다.

- 부분 격리: 선택한 API·작업자 카드만 같은 AWS 영역 내부의 논리적 격리 구역으로 이동한다.
  주변 자원은 움직이지 않고, 원래 위치는 윤곽선으로 남긴다. 실제 Pod의 물리 이동을 뜻하지 않는다.
- 환경 이전: 원본 노드를 남겨 두고 앱 실행본·작업자 배치와 데이터 동기화 카드를 목적지로 이동시킨다.
  승인 전이나 보류 상태에서는 배치 성공 이동 카드를 생성하지 않는다.
- 패치·롤백·확장: 이미지 또는 복제본 배치 카드를 대체 위치로 이동시킨다.
- 자격 회전: 자격 연결 표시를 이동시키며 실제 비밀값을 생성하거나 표시하지 않는다.
- 재기동: 같은 위치에서 새 실행본이 등장한다. 발신 차단은 노드 이동 없이 연결 상태만 바뀐다.

`requestAnimationFrame`으로 좌표를 보간하며 연결선과 차단 표시도 현재 좌표를 따라간다.
일시정지 때 현재 좌표와 진행률을 보존하고 재생 시 남은 시간부터 이어 간다.
노드 선택은 진행 중 애니메이션을 다시 시작하지 않는다. 시나리오 초기화·탭 숨김·페이지 종료 시
이전 타이머를 취소하거나 정지한다. reduced-motion에서는 바로 최종 표시 위치로 바뀐다.

브라우저에서 중간 좌표가 시작점·도착점 사이인지, 정지 중 불변인지, 재생 뒤 목적 위치에
도달하는지 확인했다. 이전 장면에서 이동 카드 3개와 원본 보존·목적지 요청 경로 대기를
확인했으며, 네트워크 검증에서도 외부·제품 API·변경 요청 0건을 유지했다.
출처·실행 권한·실환경 연결은 변경하지 않았다.

노드 크기·상태·동작은 유지하고 설명·상태 행 간격만 조정했다.

실제 로컬 브라우저 13항목이 통과했다. 추가로 모든 유형에 영어 부제가 있고,
14개 노드의 영어 이름이 카드 너비를 넘지 않는지 확인했다. 모바일 배치·이동·정지·재생과
외부·제품 API 요청 0건도 유지했다. 실행·승인 계약과 실환경 연결은 변경하지 않았다.

## 사이드바 슬라이드와 메인 영역 대응

가장 왼쪽 워크스페이스 메뉴를 접고 펼치는 버튼을 상단에 추가했다.
데스크톱에서는 사이드바의 슬라이드와 메인 여백 변화를 280ms로 함께 처리한다.
메인 영역의 고정 최대 너비를 없애고, 지도의 상세 패널·대응 유형·상태 카드가
실제 사용 가능한 콘텐츠 너비에 따라 재배치되도록 container query를 적용했다.
메뉴 상태만 로컬에 보존하며 대응 실행 상태나 승인·자격은 저장하지 않는다.

900px 이하에서는 메뉴가 메인 위에 겹쳐 열린다. 닫기 버튼·바깥 영역·Esc·메뉴 선택으로
닫을 수 있다. 열린 메뉴 안으로 키보드 초점을 제한하고 배경은 inert 처리한다.
닫거나 화면 크기가 바뀌면 초점을 접근 가능한 토글 버튼으로 돌려준다.
숨긴 메뉴도 inert로 처리해 키보드가 화면 밖으로 이동하지 않게 했다.
reduced-motion에서는 슬라이드 전환을 생략한다.

실제 Chrome에서 접는 도중 중간 여백이 존재하는지, 접은 뒤 메인이 넓어지는지,
1200px 화면에서 메뉴 상태에 따라 지도 상세 패널이 재배치되는지 확인했다.
새로고침 후 선택 유지, 모바일 배경·키보드·닫기 경로, 가로 넘침과 기존 이동 흐름을 포함해
17항목을 검증했다. 외부·제품 API·변경 요청은 0건이다.

## 대응 흐름과 주입 콘솔 통합

사용자가 지정한 지도 상단 영역을 `대응 흐름 · 주입 콘솔`로 변경했다.
기존 단계 표시와 승인 패널을 같은 영역으로 옮기고, 지도·움직임·확대 도구는 그 아래에 유지한다.
선택 유형에 맞는 주입 명령을 입력하거나 예시를 채워 실행할 수 있다.

```text
inject lateral-movement --target api,worker
```

명령은 서버 셸이나 kubectl로 전달하지 않는다. 브라우저의 고정 문법만 해석해 현재
시나리오 이벤트·대상 집합과 대조한다. 접수 시 기존 상태 모델의 이상 주입으로 한 번 진행하고
자동 재생을 시작한다. 승인이 필요한 단계에서는 기존과 같이 멈춘다.
현재 단계와 대상 범위를 벗어난 요청, 재주입, 추가 인자, 셸 치환·체이닝은 거부한다.
일반 상태 조회나 도움말이 실행·승인을 만들지 않는다.

`help`, `status`, `clear`와 로그 지우기를 제공한다. 기록은 textContent로만 표시하고
최대 80행·행당 500자, 명령은 최대 256자로 제한한다. 화면의 기록은 운영 감사 로그가 아니다.
유형 변경·초기화 시 입력·로그·이전 자동 재생을 함께 초기화한다.

- `commands.mjs`: 9가지 고정 주입 이벤트와 대상 범위, 명령 형식 검사.
- `injection_console.mjs`: 입력·피드백·모델 단계 기록과 UI 이벤트 연결.
- 명령 시험 5개 통과: 전체 유형, 누락·중복·범위 초과, 셸·HTML·추가 인자, 반복 주입, 승인 우회 거부.
- 실제 Chrome 21항목 통과: 주입 → 흐름 진행 → 승인 대기, 9개 유형의 주입, 입력 거부와 DOM 비실행,
  도움말·조회·로그 지우기, 기존 반응형·애니메이션·접근성 확인.

외부·제품 API·변경 HTTP 요청과 브라우저 오류는 0건이다. 기존의 실환경 미연결 경계를 유지했다.

사용자 후속 요청으로 다음 단계·자동 재생·초기화·재생 간격·검증 결과와 현재 진행 안내도
같은 흐름·주입 콘솔 영역으로 이동했다. 지도 아래의 중복 조작 영역은 제거했다.
기존 버튼 ID·승인 조건·재생 동작은 유지한다. 브라우저에서 제어가 지도 위에 있고
버튼이 중복되지 않으며, 승인 뒤 실행·검증까지 기존 흐름으로 진행하는지 확인한다.


## 한 화면 보기

흐름·콘솔·지도·단계 버튼을 동시에 보려는 요청에 따라, 상단에 `한 화면 보기` 전환을 추가했다.
기존 DOM과 브라우저 세션을 유지하며 CSS 배치만 바꾼다. 운영 연결이나 실행 권한은 추가하지 않는다.

- 상단: 네 가지 상태 요약과 단계 흐름·승인 안내.
- 왼쪽: 9개 대응 유형. 공간 확보를 위해 기존 전역 메뉴는 진입 시 접는다.
- 중앙: 현재 높이에 맞춘 지도·움직임·확대 도구.
- 오른쪽: 주입 기록과 명령 입력. 기록만 패널 안에서 스크롤한다.
- 하단: 다음 단계·자동 재생·초기화·간격·검증 결과·현재 안내.
- 자원 상세는 지도 도구의 버튼으로 펼친다. 닫힌 상세는 inert/aria-hidden 처리한다.

창이 1180×700 CSS px보다 작으면 일반 스크롤 배치로 복귀한다. 대응 단계나 승인 상태는
변경하지 않는다. `전체 내용 보기` 또는 Esc로 원래 배치로 돌아가고, 상세를 연 상태에서는
첫 Esc가 상세만 닫는다. 거버넌스·타임라인 탐색도 일반 배치로 복귀해 해당 내용을 표시한다.

검증 근거는 `/private/tmp/sova-response-focused-final-20261109`에 기록한다.
브라우저 검증에는 1440×900, 1366×768, 1280×800, 1180×700에서 9개 대응 유형의
정상·승인 대기 화면, 지도·입력·단계 버튼의 경계, 상세 접기와 Esc, 모바일 자동 복귀를 포함한다.
이 검증은 로컬 브라우저 배치·동작 확인이며 실제 클러스터 실행 검증이 아니다.

기존 회귀를 포함한 Chrome 검증 22항목을 통과했다. 제품 API·외부 요청·변경 요청·브라우저 오류는 0건이다.


## 운영 콘솔 명령 확장: 격리 복귀 모델

사용자 요청에 따라 주입 이외의 조회·승인·관찰·복귀 명령을 준비한다. 첫 변경은 브라우저
상태 모델의 복귀 계약이며, 실제 셸·클러스터 실행기를 추가하지 않는다.

`isolate`·`segment`의 격리 검증을 통과해 대응이 완료된 뒤 명시적인 복귀 요청을 받을 수 있다.
원본 재검증 → 원본 위치 복귀·연결 확인 → 복귀 완료를 구분한다. 재검증 전과 복귀 중에는
기존 연결 차단을 유지한다. 실패·불명확이면 복귀를 보류하고 자동 재시도하지 않는다.
DB 이전·이미지·자격증명 등의 복구는 별도 인수 계약 없이 초기 상태로 되돌리지 않는다.
복귀 뒤에도 사고 보류·전체 이력·mock 출처·실행 권한 없음은 유지한다.

모델·움직임 시험 26개 통과: 허용 유형·단계 제한, 중복 요청, 검증 전 차단 유지,
실패·불명확 시 원본 경로·writer 보존, 선택 대상의 복귀 위치와 이력 보존을 포함한다.


복귀 검증의 결과 입력은 격리 검증 결과와 분리했다. 격리 성공이 원본 복귀 성공을 뜻하지 않도록,
복귀 요청에 별도 pass/fail/unknown 결과를 고정하며 진행 중 선택값 변경은 반영하지 않는다.
격리 결과가 실패·불명확한 실행은 복귀 요청 자체를 거부하고, 별도 점검 대상으로 남긴다.
검증하지 않은 결과 문자열도 복귀를 시작하지 않는다. 모델·움직임 검증 27개를 통과했다.


## 주입 콘솔에서 운영 콘솔로 확장

고정 명령을 파싱하는 브라우저 운영 콘솔을 추가했다. 터미널 출력·지도·요약·진행 표시·기록
모두 동일한 session/snapshot을 사용한다. 임의 셸·kubectl·프로세스·클러스터 요청은 실행하지 않는다.
승인 버튼과 `response approve`는 같은 함수로 선택된 대응을 승인하고, 실행·검증을 자동 진행한다.
사전 승인이 없으면 승인 대기에서 멈추며 시간 경과·관찰·재개 요청으로 승인을 대신하지 않는다.

| 명령 | 동작 |
|---|---|
| `workload status` (`status` 별칭 유지) | 현재 단계·경로·writer·격리 수·구성 요소 상태 조회 |
| `incident inspect` | 선택된 유형의 이상 근거·대상·대응 계획·검증 기준·보류 조회 |
| `response watch` | 현재 상태·최근 이력과 이후 이벤트 출력 관찰. 실행·승인 없음 |
| `response approve` | 승인 대기인 현재 대응만 승인하고 실행·검증까지 자동 진행 |
| `response pause` / `response resume` | 진행·움직임 정지와 재개. 상태·승인·차단은 유지 |
| `recovery start` | 검증 완료된 isolate/segment만 원본 재검증 후 복귀 |
| `help` / `clear` | 지원 명령 안내 / 콘솔 표시만 지우기 |

주입 대상·이벤트 고정 검사는 유지한다. 추가 인자·범위 확대·체이닝·개행·프로토타입 속성명과
승인 우회 명령은 거부한다. 조회는 session을 변경하지 않는다. 중복 승인·중복 복귀도 거부한다.
출력은 계속 textContent·행 수/길이 제한을 적용한다. 터미널 승인과 화면 승인은 같은 승인 처리 함수를 사용한다.

복귀는 별도 `복귀 검증` 선택값을 요청 시 고정한다. 진행 중 선택값을 바꿔 보류를 통과시킬 수 없다.
`recovery_checking`에서는 격리 유지, `recovery_restoring`에서는 선택 대상만 원래 위치로 이동하며
연결은 계속 차단한다. `recovered`에 도달해야 연결을 복구한다. 실패·불명확은 `recovery_held`에서
멈추고 자동 재시도하지 않는다. 승인·원본 복귀는 사고 보류를 해제하지 않는다.
유형 변경·초기화·페이지 비활성화 시 기존 재생을 멈춰 이전 실행이 새 흐름을 진행하지 않게 한다.

기본 브라우저 명령 시연은 `segment` 유형에서 다음 순서로 진행한다.
주입 이후 승인 대기에 도달한 뒤 승인하며, 복귀는 격리 검증 완료 이후 요청한다.

```text
workload status
inject lateral-movement --target api,worker
incident inspect
response approve
response watch
recovery start
```

DB 이전·이미지·자격증명의 복구는 이 명령으로 초기화하지 않는다. 출발지 데이터 최신화·자격 폐기·
이미지 호환성 등의 별도 복구 조건이 필요하기 때문이다. 결과 선택과 브라우저 시나리오는 실제
HTTP·정책 거부·복구 측정 증거가 아니며, 내보내기의 mock/actual_execution:false 표시는 유지한다.

검증 근거: `/private/tmp/sova-response-operator-final-20261109`.

기준 UI 커밋은 `b44c66f`이며 복귀 모델(`e4b0664`), 복귀 결과 분리(`43102ad`)를 순서대로 적용했다.
최종 검증: 모델·명령·움직임 단위 시험 36개, 정적 서버 경계 시험 3개, Chrome 28항목 통과.
외부·제품 API·변경 HTTP 요청·브라우저 오류는 0건이다. 실제 클러스터 관측·변경·인수는 수행하지 않았다.


## 화면 복원: 기존 주입 콘솔 배치 유지

사용자 요청에 따라 운영 콘솔 확장 직전(`b44c66f`)의 화면 구성을 복원했다.
`대응 흐름 · 주입 콘솔` 제목, 기존 콘솔 도구와 한 화면 보기 배치를 유지하고, 새로 넣은
상태·사고·관찰·승인·복귀 버튼과 별도 복귀 검증 선택칸을 제거했다.

명령·승인 후 자동 진행·원본 재검증·실패 시 격리 유지 기능은 유지한다. 선택한 대응의
격리 검증이 완료되면 기존 `검증 결과` 선택칸을 `복귀 검증`으로 전환한다. 이때 결과 변경은
진행 이력을 초기화하지 않으며 복귀 요청 시 고정된다. 복귀 중 선택값 변경은 무시한다.
초기화할 때에는 기존 대응의 검증 결과를 유지하고 복귀 결과만 초기화한다.

검증 근거: `/private/tmp/sova-response-ui-restored-20261109`.

복원 후 기존 Chrome 검증 28항목이 통과했다. 명령·자동 진행·복귀 결과 고정과 한 화면 배치를 유지하며 외부·제품 API·변경 요청과 브라우저 오류는 0건이다.
