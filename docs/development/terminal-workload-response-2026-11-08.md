# 터미널 요청과 실제 온프렘 워크로드 대응

## 목적과 구현 경계

기존 Sova 화면과 실제 AWS·온프렘 설정 관측은 유지하고, 별도로 생성한
온프렘 시험 워크로드에서 접근 시도·보류·승인·격리·대체·경로 전환을 확인한다.
`demo/onprem_response`의 기존 원장·가드·Kubernetes 어댑터를 재사용한다.
제품 T10 승인이나 공유 앱의 컷오버를 대신하는 실행 경로가 아니다.

```text
소유자 터미널의 고정 attempt 명령
  → 시험 Blue Pod가 보호된 이웃 서비스에 인증 없는 HTTP 요청
  → 실제 403 + 독립 이웃 감사 + nonce·Pod UID/IP·소유 Deployment 대조
  → 사건 후 대응 계획 결속 → 별도 사람 승인
  → 원본으로의 새 연결 격리 확인 + 이웃 정상 응답
  → Green 기동·HTTP 확인 → 시험 진입점 전환·readback
  → 화면 증거 만료 → 소유 namespace UID 대조·정리
```

403은 고정 접근 통제가 실제 요청을 거부했다는 증거다. 취약점 악용, 침해 탐지,
일반 공격의 분류 또는 임의 앱 자동 복구를 입증하지 않는다. 원본 Pod에서 발생한
요청임을 확인한 후 원본을 대상으로 대응하며, 요청을 거부한 이웃은 격리하지 않는다.

## 코드

| 파일 | 책임 |
|---|---|
| `terminal_fixture.py` | 고정 이웃 HTTP 요청, 1회 시도 제한, 독립 감사 |
| `terminal.py` | 직접 API 전송, 현재 신원 대조, 대응 결속·readback·정리 |
| `terminal_supervisor.py` | 사건 후 계획 승인과 최종 관측 게시에 결속된 완료 상태 |
| `terminal_cli.py` | 고정 개인 시험의 attempt/status/approve/stop |
| `terminal_projection.py` | 실제 관측만 기존 조회 전용 그래프 형식으로 변환 |
| `controls.py` | 짧은 유효기간·현재 계획·소스 SHA에 결속한 제어 요청 |

연결은 등록된 개인 Tailscale Kubernetes API를 사용한다. 새 port-forward,
공개 서비스, 클러스터 역할, Secret 또는 공유 namespace를 만들지 않는다.
최대 8분, 새 namespace 3개와 작은 무상태 Pod 최대 4개로 제한한다.
명령·URL·자격증명·대상을 브라우저나 모델이 지정할 수 없다.

## 안전 조건과 한계

- 처음 표시한 계획에 대한 승인은 사건 이후 생성한 대응 계획을 승인하지 않는다.
- 실제 요청 의도는 전송 전에 저장한다. 응답 유실·실패를 자동 재시도로 덮지 않는다.
- 최종 효과 영수증이 먼저 생겨도 최종 readback 그래프가 게시되기 전에는 완료하지 않는다.
- 그래프 HMAC·소스 SHA·현재 session·계획·관측 revision을 검증하며, 만료·권한 회수 시 철회한다.
- 현재 격리 실측은 독립 Pod에서 원본으로 향하는 새 연결 거부와 이웃 정상 응답이다.
  기존 연결 종료나 원본의 외부 통신 차단 전체를 검증한 것으로 확대하지 않는다.
- 개인 시험 승인은 제품 T10 승인이나 기업 사용자 인증을 대신하지 않는다.
- AWS→온프렘 데이터 이전·무중단 운영·제품 해피패스 완료로 기록하지 않는다.
- Python fixture 이미지는 공식 digest에 고정했다. Windows에서 검사한 security
  이미지의 취약점 0건·90분 지속 시험 결과와 합치지 않는다.

## 검증과 개발 기록

- 초기 정적 자산 로그인 경합은 자원 생성 전에 중단했다. 공개 정적 코드와 인증이
  필요한 상태·제어 API를 구분했다. 상태·제어의 인증은 유지했다.
- POST 경로에 조회용 nonce를 붙여 발생한 404를 수정하고 회귀 시험을 추가했다.
  실패한 시험의 소유 자원은 정리했다.
- `a4674e36c32e9cd407319d7cf088553250b38c6f`에서는 실제 403·주체·독립 감사,
  네 가지 대응 효과와 정리를 확인했다. 다만 브라우저가 마지막 그래프보다 먼저
  완료를 읽어 복구 단계 표시가 미확인이었으므로 완전 통과로 사용하지 않는다.
- 후속 시험들은 요청 경로의 503으로 승인 전에 중단했고 자원 부재를 확인했다.
  원인을 추측해 성공 처리하지 않았다. 고정 fixture 오류 코드만 비공개로 남기도록
  개선했으며 임의 응답 본문·예외 메시지는 보존하지 않는다.
- 실제 원인: Kubernetes의 Service 환경변수 자동 주입으로 `NEIGHBOR_PORT`가
  숫자가 아닌 `tcp://…` 값이 됐다. 고정 fixture의 예외 로그로 확인했다.
  `SOVA_TRIAL_NEIGHBOR_PORT`로 분리하고 `enableServiceLinks=false`를 선언했다.
  자동 주입값이 존재하는 로컬 HTTP 회귀에서도 전체 전달·감사가 통과한다.

원본 로그·접속 자료·Pod UID·감사·효과 영수증·화면·영상은 비공개 검증 폴더에
보존한다. 공개 문서에는 운영 식별자나 접속 nonce를 넣지 않는다.

## 최종 실제 인수

실행 생산자는 **`3ab5dd3aa2aaf4bc2169526f67e9de3f1d4cf7ba`**다.
이 결과를 뒤의 문서 커밋이나 다른 security 이미지 시험으로 바꾸어 기록하지 않는다.

- 실제 터미널 요청의 HTTP 403·Pod UID/IP·Deployment 소유권·독립 이웃 감사 확인.
- 사건 후 별도 승인, 원본 새 연결 차단과 이웃 정상 응답 확인.
- Green 실제 기동·HTTP 응답·시험 진입점 전환과 readback 확인.
- 지도 1개 워크로드 격리, 8개 단계 모두 현재 근거로 확인됨.
- 브라우저 오류 0, 모바일 가로 넘침 없음, 세션 회수 후 시험 자료 철회 확인.
- 세 개의 소유 시험 namespace 모두 부재 확인. 기존 공유 자원 변경 없음.
- 집중 Python 시험 **52개** 통과. 고정 actor→neighbor와 probe→actor→neighbor
  HTTP는 실제 로컬 프로세스이며, 클러스터 결과와 별도다.

원본 UI 화면과 영상은 비공개로 보존했다. 공개 요약에는 원본 증거의 SHA-256만
남겼다. 최초 실패·부분 완료·원인 확인용 실행의 원본도 덮어쓰지 않았다.
