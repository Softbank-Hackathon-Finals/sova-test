# 이전 대상에서의 기능과 보호 재현

상태: 목표 계약. 구성 이름의 동일성이 아니라 보호 목적과 업무 동작의 충족 여부를 검증한다.

## 공통 판정 모델

각 요구는 `requirement_id / source evidence / target implementation / scope / revision / validation / expiry / exception`에 연결한다. 상태는 충족·위반·미확인·승인된 예외다. 기능의 provider 제공 여부, Sova 어댑터 구현 여부, 해당 환경 검증 여부를 분리한다. 미확인된 필수 보호는 실행을 차단한다.

| 요구 | 클라우드 경로 | 온프레미스의 구현·시험 |
| --- | --- | --- |
| 신원·권한 | IAM·workload role·단기 자격 | 조직 OIDC·앱별 서비스 신원·RBAC·짧은 인증서, 실제 교차 앱 거부 |
| 비밀 | Secrets Manager·KMS | 고객 비밀 저장소·키 접근 분리·회전·복구, 앱에 필요한 참조만 전달 |
| 네트워크 | SG·사설 경로·경계 제어 | 검증된 CNI NetworkPolicy·방화벽·egress, metadata·관리망·공유 서비스 예외 확인 |
| 암호화 | TLS·저장 암호화·관리 키 | 신뢰 체인·hostname·키 보관·권한·회전·폐기·backup 복원 확인 |
| 감사 | 서비스별 감사 이벤트 | 신원·행위·대상·결과·정책 revision의 중앙 수집, 변경 방지 저장·보존·검증 |
| 가용성 | 다중 장애 영역·관리형 복구 | 노드·전원·스토리지 실패 영역과 복제·복구 실측 |
| 관측 | 서비스별 지표·로그 | OTel 수집·누락/만료·알림·제어면 단절 시 보존 |

Kubernetes namespace만으로 적대적 테넌트의 충분한 격리를 선언하지 않는다. 민감도에 따라 전용 노드·클러스터·프로세스·DB·키·수집 경계를 고른다. k3s 단일 노드를 Multi-AZ와 동등하게 표시하지 않는다.

## 대상의 장점 활용

동일 기능 최소 재현과 대상 최적화를 분리한다. 이전 후 관리형 DB·객체 저장소·로컬 AI 같은 이점은 비용·락인·보호 변화와 함께 별도 후보로 제안한다. 데이터 위치·라이선스·지연·복구 요구를 통과한 후보만 비교한다. 검증하지 않은 관리형 기능을 자동 치환하지 않는다.

## 게이트와 증거

배포 전 정책 검사 → 실제 자원 readback → 정상 동작·권한 거부 시험 → 장애·회전·복원 시험을 연결한다. 하나의 시험이 모든 통제를 증명하지 않는다. 화면은 양쪽 요구·구현·근거·차이·예외 만료를 보여준다. IAM→RBAC 변환은 권한 의미·상속·관리 권한 차이를 검토한 결과여야 한다.

## 2026-11-02 구현 경계

상담 reference workload의 실제 컨테이너에서 인증서/hostname 검증 PG 연결, 잘못된 CA·비밀번호의 거부와 복원, 비루트·읽기 전용 실행, 재시작 후 DB·파일 보존을 확인한다. 운영자 schema/초대 관리 도구를 서비스 이미지에 넣지 않는다.

S3 선택은 명시적 환경 설정이며 bucket owner·동일 계정/리전의 정확한 KMS key ARN·고정 prefix·조건부 PUT·checksum·크기·전송 한도를 요구한다. 임의 AWS endpoint와 cloud 실패 후 local fallback은 허용하지 않는다. 이 경로의 현재 검증은 SDK 응답 대체물이며 실제 S3/KMS 자격이 아니다. Local volume의 암호화·HA나 Secrets Manager→온프렘 비밀 저장소의 운영 동등성은 별도 시험이다.
