# 실제 온프렘 워크로드 대응 시험

등록된 개인 직접 API 접속 도구 안에서만 실행하는 운영자 전용 시험이다.
임의의 운영 앱이나 기존 namespace를 받지 않는다. 매 실행마다 세 개의
새 namespace와 최대 네 개의 작은 무상태 HTTP Pod만 사용한다.

## 확인할 흐름

1. 원본 API와 독립 서비스의 실제 HTTP 응답을 확인한다.
2. 원본 API에 `readOnlyRootFilesystem=false`를 주입하고 실제 설정을 수집한다.
3. 기존 `SecurityResponseBinding`·`SecurityResponseGuard`로 네 단계 계획을 결속한다.
4. 기존 `EffectExecutor`·SQLite 효과 원장을 통해 원본 격리, 대체 기동,
   대체 HTTP 확인, 전용 시험 진입점 전환을 수행한다.
5. NetworkPolicy 내용뿐 아니라 별도 Pod에서 새 연결이 거부되는지 확인한다.
   같은 확인 Pod에서 이웃 서비스의 응답은 유지되어야 한다.
6. 관측을 HMAC으로 결속해 조회 전용 콘솔에 제공한다.
7. 종료 전에 화면 근거를 만료시키고, 소유 namespace UID를 대조한 뒤 정리한다.

## 경계

- 기존 `target-dev`, DB, 클러스터 RBAC, AWS와 플랫폼 호스트는 변경하지 않는다.
- 현재 개인 API 권한으로 수행하는 명시적인 전용 시험이다. 제품 T10 승인,
  T19 통제 전체 통과, 실제 공격 탐지, 클라우드 간 이전을 의미하지 않는다.
- 격리 증거는 해당 독립 확인 Pod에서 원본으로 향한 새 HTTP 연결에 한정한다.
  모든 통신·기존 연결·egress가 검증됐다고 확대하지 않는다.
- NetworkPolicy의 선택자는 앱과 구성 요소를 모두 포함한다.
- 효과의 응답이 불명확하면 재실행하지 않는다. 원장과 실제 자원을 조회해 인수한다.
- 시험 런타임은 명시적으로 지정한 공식 Python digest다. 보안 취약점 전체를
  검사한 서비스 이미지라는 주장은 하지 않는다.
- 10분 개인 자격보다 짧은 실행 기한, 자원 할당량, 비특권 컨테이너를 사용한다.
- 비공개 실행 폴더에는 신원·UID·진단·영수증이 남는다. 공개 저장소에 넣지 않는다.

시험 도구는 `demo/`에만 있으며 설치 패키지와 제품 실행 경로에 포함되지 않는다.
소스 커밋을 먼저 고정해야 실제 실행할 수 있다. 콘솔은 별도 조회 프로세스이며
Kubernetes 자격이나 변경 API를 받지 않는다. 명령 예시의 경로·등록 프로필은
운영자의 비공개 접속 자료를 사용한다.
